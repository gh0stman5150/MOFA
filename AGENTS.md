## Purpose and authority

MOFA contains Microsoft application metadata feeds, reset tools, configuration
profiles and supporting assets. This file owns repository contributor guidance.
In MacProjects, consult the [shared workspace rules](../AGENTS.md#shared-rules).
[CONTRIBUTING.md](CONTRIBUTING.md) is the human maintenance guide and must stay
consistent with this file.

The [Copilot entry point](.github/copilot-instructions.md) links here and does
not maintain a second copy of these rules.

## Layout and scoped instructions

- .github/actions/: Python HTTP helpers, generators and README template.
- .github/requirements.txt: pinned Python dependencies.
- latest_raw_files/: generated XML, JSON, YAML and RSS feeds.
- tests/: pytest coverage for HTTP, automation, data and shell safety.
- office_reset_tools/mofa_community_maintained/scripts/: active Jamf endpoint
  tools; follow its [AGENTS.md](office_reset_tools/mofa_community_maintained/scripts/AGENTS.md)
  for the mandatory Jamf execution contract, Zsh conventions and local checks.
- office_reset_tools/office_reset_archived/: historical scripts and packages.
- mobileconfig_profiles/: XML configuration profiles for MDM review.
- icons/ and guides/: static assets and operator references.

## Feed and profile invariants

Python generators and tests are development/CI tools, not Jamf policy scripts.
Use Python 3.13 to match CI and the pinned requirements file with pip.
Reuse http_client.py and existing error-handling/test patterns.

The root README is generated by .github/actions/update_readme.py. Change
durable prose in that template and keep rendered navigation consistent.
Do not manually edit release values or silently refresh datasets during an
unrelated change. Use the runner for an intentional network refresh.

The scheduled update workflow validates output and creates/updates a PR for
substantive changes; it does not automatically merge. Preserve that boundary
and timestamp-only change detection. Check product IDs, fields and timestamps
before treating cached data as current vendor information.

Preserve archived provenance. Review profile identifiers, payload scope and
supported settings before deployment; plist syntax alone does not prove MDM
acceptance or application support.

## Validation

From this repository in an activated Python 3.13 environment:

```bash
python -m pip install --disable-pip-version-check -r .github/requirements.txt
python -m compileall -q .github/actions tests
python -m pytest -q
git diff --check
```

Only for an intentional feed refresh with network access:

```bash
python .github/actions/run_generators.py
python -m pytest -q
git diff -- README.md latest_raw_files
```

Add focused tests for changed generators/helpers, using mocked HTTP and
synthetic fixtures. For endpoint script work, use the linked nested guide.
Keep CONTRIBUTING.md and directory READMEs synchronized with workflow changes.

## Known gaps

Verify unexpected App Store product identities and placeholder-like profile
UUIDs before operational use. No community package build pipeline is provided.
Check dataset timestamps and pending update PRs when data appears stale.
