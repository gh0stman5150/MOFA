## Purpose and authority

MOFA contains Microsoft application metadata feeds, reset tools, configuration
profiles and supporting assets. This file owns repository contributor guidance.
In MacProjects, consult the [shared workspace rules](../AGENTS.md#shared-rules).

The [Copilot entry point](.github/copilot-instructions.md) links here and does
not maintain a second copy of these rules.

## Layout and scoped instructions

- .github/actions/: Python HTTP helpers, generators and README template.
  standalone_feed.py holds the code shared by the latest, preview and beta
  standalone generators; appstore_feed.py the code shared by the iOS and
  macOS App Store generators.
- .github/requirements.txt: pinned Python dependencies.
- latest_raw_files/: generated XML, JSON, YAML and RSS feeds. Excluded from
  search by [.ignore](.ignore); query one format with jq or xmllint rather
  than reading files whole.
- tests/: pytest coverage for HTTP, automation, data and shell safety.
- office_reset_tools/mofa_community_maintained/scripts/: active Jamf endpoint
  tools; follow its [AGENTS.md](office_reset_tools/mofa_community_maintained/scripts/AGENTS.md)
  for the mandatory Jamf execution contract, Zsh conventions and local checks.
- office_reset_tools/office_reset_archived/: historical scripts and packages.
- mobileconfig_profiles/: XML configuration profiles for MDM review.
- icons/ and guides/: static assets and operator references.

## Feed and profile invariants

Python generators and tests are development/CI tools, not Jamf policy scripts.
Use Python 3.13 to match CI and the pinned requirements file with pip.
Reuse http_client.py and existing error-handling/test patterns.

Generators report through logging, not print. A fetch or hash failure that
keeps the cached entry logs WARNING; an entry that would be dropped or a feed
that cannot be parsed logs ERROR, which fails run_generators.py. Stream each
installer once for both digests. update_readme.py renders download links from
the feed entry that supplies the version and hash, and exits 1 without
writing README.md when a feed it renders is unusable.

A cached feed is reused per package: one malformed cached entry is skipped,
not the whole cache. A source page that alone supplies a whole feed (update
and CVE history) logs ERROR and keeps the existing files when it cannot be
fetched or parsed. An App Store entry uses the first search result whose
seller or artist is Microsoft, or whose bundleId equals the entry's optional
bundle_id; with no match it keeps the cached entry and logs ERROR until the
search term is corrected, a bundle_id is pinned or the app is removed.

Generators run, and configure logging, only from main() or behind
`if __name__ == "__main__"`, so tests import them without side effects and
replace http_get in the module that sends the request.

The root README is generated by .github/actions/update_readme.py. Change
durable prose in that template and keep rendered navigation consistent.
Do not manually edit release values or silently refresh datasets during an
unrelated change. Use the runner for an intentional network refresh.

The scheduled update workflow validates output and creates/updates a PR for
substantive changes; it does not automatically merge. Preserve that boundary
and timestamp-only change detection. has_substantive_changes.py exits 0 for a
substantive change, 1 when only generated timestamps changed (the workflow
restores the files) and 2 when the comparison fails (the workflow fails
instead of discarding the data). Only the update job joins the
mofa-generated-data concurrency group, so hourly refreshes never queue or
cancel push and pull request validation. Check product IDs, fields and
timestamps before treating cached data as current vendor information.

The generated-data PR is opened with the default GITHUB_TOKEN, so GitHub
starts no workflows for it and it carries no status checks. Its body links
the generating run, where generation, the test suite and change detection
ran; review that run before merging. Closing and reopening the PR runs pull
request validation for its current head commit only. A required status check
on the base branch would block this PR until a workflow-triggering token is
configured.

Preserve archived provenance. Review profile identifiers, payload scope and
supported settings before deployment; plist syntax alone does not prove MDM
acceptance or application support.

## Validation

From this repository in an activated Python 3.13 environment:

```bash
python -m pip install --disable-pip-version-check -r .github/requirements.txt
python -m compileall -q .github/actions tests
python -m pytest -q
git diff --check
```

Only for an intentional feed refresh with network access:

```bash
python .github/actions/run_generators.py
python -m pytest -q
git diff -- README.md latest_raw_files
```

Add focused tests for changed generators/helpers, using mocked HTTP and
synthetic fixtures. For endpoint script work, use the linked nested guide.
Keep the README template and directory READMEs synchronized with workflow changes.

## Known gaps

The App Store publisher check does not catch a different Microsoft app
ranking first (for example a search returning Microsoft To Do); pin bundle_id
for such entries. Verify placeholder-like profile UUIDs before operational
use. No community package build pipeline is provided. Check dataset
timestamps and pending update PRs when data appears stale. The generated-data
PR has no status checks of its own (see the update workflow above). The
OneDrive Upcoming Production Ring reads the same manifest as the Production
Ring, so the feed publishes two identical entries; it needs its own confirmed
manifest URL or removal from the feed.
